# 预览合成方案决定
外部 `mpv.exe` 旁挂进程不是产品要求。ResubWinny 正在迁移到自己的动态 `libmpv` 客户端 ABI。Windows x86_64 运行时以可替换的 LGPL 依赖项形式捆绑；macOS 与 Linux 使用各自平台运行时，遵循同一套 ABI 合约。

| 后端 | 平台 | 字幕保真度 | 主要权衡 |
| --- | --- | --- | --- |
| `libmpv-render` | Windows/macOS/Linux | 最高；在同一个表面上合成视频与 libaribcaption RGBA | 需要 libmpv 集成和本机纹理/表面循环 |
| mpv `overlay-add` | mpv 支持的平台 | 对低频 RGBA 帧保真度高 | 原始像素上传和 mpv 版本/VO 限制 |
| 本机窗口覆盖层 | Windows 优先 | 高 | HWND/Z 顺序、调整大小、DPI 和平台特定代码 |
| WebView 图像层 | 全部 | 适合档案检查 | 无法可靠地覆盖嵌入的本机子窗口 |
| ASS 字幕轨道 | 全部 | 近似 | 丢失精确的 ARIB 字符单元、ruby、DRCS 和背景语义 |

所选的 Windows 路径是 `libmpv-render`。它把视频与字幕保持在同一个由项目自己持有的 WGL 表面上，避免 WebView 与本机窗口的层叠问题。只有在渲染 API 或 WGL 启动失败时，`wid` 加 `overlay-add` 的客户端路径才作为按来源生效的兼容性后备保留。ResubWinny 不会启动 `mpv.exe`，也不使用 JSON 命名管道。macOS 与 Linux 将采用同一套字幕模型，但其本机渲染表面尚未实现。

类型化的 `get_preview_capabilities` API 对外暴露这一选择，而不让 UI 依赖 Windows 特定细节。无论走渲染路径还是其客户端覆盖层后备，Tauri 后端都通过类型化的 `sync_preview_overlay` 操作采样 mpv 时间，并在上传之前把返回的本机字幕平面与上一个平面作比较。WebView 可以调度该操作，但不计算媒体时间、不合成字幕、也不实现后备时钟。因此，未发生变化的字幕平面不会触发又一次原始像素 IPC 传输；这样，长而稀疏的录像也能保持有界，无需预先加载其字幕时间线。发生变化的 RGBA 平面会写入每次预览各自的临时 BGRA 文件，并按 mpv 已记录的 `overlay-add` 文件/偏移参数传给它；预览停止时删除该临时文件。Tauri 的档案读取器只保留单向前进的游标和至多 128 个活动区间；向后跳转会重置这个有界游标，因此它绝不会把长达数小时的时间线载入内存。mpv 时间查询的超时很短；当 IPC 尚未就绪时，后端返回 `awaiting-player-time` 并让上一个平面留在原处，而不是凭本地时钟编造一条时间线。

`get_preview_runtime` 报告已加载的运行时路径，以及该运行时是否导出 libmpv 渲染 API。在 Windows 上，若渲染 API 完整，则默认选择本机渲染路径；若某个来源无法初始化该路径，该次预览会安全回落到客户端覆盖层路径。一个专用的本机线程持有由项目自己创建的 WGL 上下文、`vo=libmpv` 实例与渲染上下文。它在 `loadfile` 之前创建渲染上下文，处理有界的控制/调整大小/时间消息，对待处理帧至多每 16 毫秒泵送一次，在默认帧缓冲区上呈现，并在同一个 WGL 上下文仍为当前上下文时释放渲染上下文。这样，脆弱的 ABI 生命周期与线程顺序都被收在后端内部。

同一渲染线程只接受后端合成的 BGRA 字幕平面。平面发生变化时，它上传有界的 OpenGL 纹理，并在 mpv 视频帧之后混合该纹理；WebView 从不接收视频帧，也不执行字幕布局。它向 libmpv 查询显示正确的视频宽高比，并把字幕平面映射到由此得到的、排除上下或左右黑边的视频内容视口；若媒体参数尚未就绪，则安全回落到整个表面并重试。一旦运行时暴露完整的渲染 API，Windows 路径即可通过类型化能力合约取得。它请求 `hwdec=auto-safe`，随后在可得时报告 libmpv 实际选定的 `hwdec-current`。这可能使用兼容的回拷（copy-back）加速，但不构成零拷贝 D3D/ANGLE 硬件解码的声明。下文描述的真实语料 Windows 4K 长时门禁已完成。独立的 2K/8K 门禁、参考截图比对与 DPI 审查仍属发布质量工作，而不是隐藏的后备路径。

`scripts/validate-preview.ps1` 是 Windows 原生路径的冒烟门禁。它使用通过 `ARIB_FIXTURE_DIR` 提供的合法本地录像，创建真实的 WGL 宿主，加载捆绑的 libmpv 运行时，启动专用渲染 Worker，并要求得到一个非均匀的解码视频帧缓冲区，以及一次后端 RGBA 字幕纹理的上传与清除，且过程中不出现 Worker 错误。它在同一渲染线程上抓取 WGL 后台缓冲区，并断言上传的不透明绿色测试纹理确实出现在抓取到的 RGBA 像素中。`bs4k_test_2.ts` 冒烟测试于 2026 年 7 月 29 日通过。该门禁验证生命周期、TS 打开、视频解码、本机呈现、纹理混合与有界帧缓冲区回读。冒烟测试使用 3840×2160 HEVC 源，在 1920×1080 上抓取混合后的平面，随后将本机表面调整为 3840×2160，并要求尺寸得到保留且呈现节奏可测量。这是 Windows 路径的回归门禁，不构成 8K 吞吐量或零拷贝解码的声明。参考截图抓取、应用程序 DPI 审查与图像差异审批仍是各自独立的门禁。

传入 `-Long` 会追加一道带阈值的 120 秒 4K 播放门禁。它运行同一条进程内本机路径，保持 3840x2160 表面处于活动状态，执行三次完整的 1920x1080 字幕平面替换，并演练暂停、恢复、精确跳转与有界关闭。默认门禁阈值为：呈现帧率至少 20 帧/秒，启动至多 10 秒，控制/字幕更新延迟至多 1 秒，关闭至多 3 秒，绝对工作集至多 2048 MiB，且在 4K 基线预热之后增长至多 512 MiB。结果以带 schema 版本的 JSON 写入 `build/validation/` 下。

2026 年 7 月 30 日针对真实 3840x2160 HEVC `bs4k_test_2.ts` 的一次运行，使用 `d3d11va-copy`，在 120 秒内维持 34.74 呈现帧/秒，启动耗时 1.69 秒，工作集峰值 1526.9 MiB，预热之后增长 111.9 MiB，上传一次完整字幕平面至多耗时 34.6 毫秒，控制操作至多耗时 14.7 毫秒，并在 337 毫秒内停止，未出现渲染错误。这些是这台 Windows 机器上的回归测量值，除明确的通过/失败阈值之外，不构成普适的硬件要求。该测试装置使用 Cargo 的 test 配置，而捆绑的 libmpv 二进制、WGL 表面、解码器与合成路径都与应用程序实际使用的本机运行时一致；在打包发布版本上重跑仍是独立的产物验收步骤。
