# Windows プライベート Alpha の受け入れ基準

このマトリクスでは、合法的に保有する日本の放送録画を使用して、パッケージ化されたアプリケーションを検証します。録画、デコード済み字幕、番組名、ローカルパス、スクリーンショットは非公開のままとします。リリース時に公開できるのは、結果の概要、フィクスチャの分類、バイトサイズ、長さ、生成されたリリース成果物のハッシュ、および合否数のみです。

公開プロトコルフィクスチャはこのマトリクスの代替にはなりません。また、放送局固有の録画を模倣するためだけに合成放送ストリームを追加してはなりません。パーサーの単体テスト用フィクスチャは、境界が定められた不正入力の回帰テストに引き続き有用です。

## 候補版の識別情報

テスト前に次の項目を記録します。候補版ディレクトリの `RELEASE-MANIFEST.json` および `SHA256SUMS.txt` と一致しなければなりません。

| 項目 | 結果 |
| --- | --- |
| リリースタグ / コミット | 保留 |
| インストーラー名 / SHA-256 | 保留 |
| `RELEASE-MANIFEST.json` SHA-256 | 保留 |
| libmpv `SOURCE-RECEIPT.json` SHA-256 | 保留 |
| Windows エディション / ビルド | 保留 |
| CPU / GPU / グラフィックスドライバー | 保留 |
| クリーンインストールまたはアップグレード経路 | 保留 |

メモでは `terrestrial-a` のような不透明なローカルフィクスチャ ID を使用します。番組タイトル、放送局の番組表、ソースファイル名、ファイルシステムパスを記録してはなりません。

## 互換性マトリクス

| カテゴリ | 必要なパッケージ版ワークフローの証拠 | 合格基準 | 結果 |
| --- | --- | --- | --- |
| 地上波 TS | サービスと B24 トラックを検出し、プレビュー、タイムライン、ASS と TTML のエクスポートを実行 | 選択トラックが正しく、メモリ使用量が有界で、プレビューが使用可能で、検証済みエクスポートが空でない | 保留 |
| BS TS | サービスと字幕トラックを検出し、プレビュー、タイムライン、エクスポートを実行 | 固定 PID やファイル名を仮定せず、同じエンドツーエンド結果を得られる | 保留 |
| 長時間番組（2～4 時間） | 開く、索引付け、開始/中間/終了付近へのシーク、プレビュー、エクスポート | 無制限なメモリ増加、古いタイムライン、シークの停止、不完全な最終成果物がない | 保留 |
| DRCS | レポートを確認し、既知グリフをマッピングし、未知グリフは未解決のまま残してエクスポート | マッピングが永続化され、フォールバックが可視かつ診断可能なままである | 保留 |
| 複数サービス/トラック | 選択字幕トラックを切り替え、それぞれを個別にエクスポート | プレビュー、イベント数、証拠、エクスポートが選択した論理トラックのみに従う | 保留 |
| 破損/切り詰められた録画 | 合法的に保有する破損または切り詰められたキャプチャを検査して変換 | 処理が有界で、診断が明示的で、サービス/トラックを捏造せず、回復可能な出力が有効なままである | 保留 |
| BS4K M2TS/プライベート PES | すでに実サンプルで実証済みの経路のみを実行 | 結果を M2TS/プライベート PES TTML 対応として限定的に報告 | 保留 |
| TLV/MMTP | 合法な実サンプルが存在する場合のみ実行 | 結果は実験的かつ証拠優先のままで、一般的な BS4K/8K 対応へ昇格させてはならない | ゲート対象外 |

## エンドツーエンド字幕ワークフロー

開発サーバーや Cargo テストハーネスではなく、インストール済みアプリケーションを実行します。

1. `SHA256SUMS.txt` と照合してインストーラーのハッシュを検証し、文書化された発行元不明の警告を確認したうえでインストールします。
2. 録画を開き、検出されたコンテナー、サービス、番組メタデータの証拠、使用可能な字幕トラックを確認します。
3. ネイティブプレビューを開始し、複数位置でシークおよび一時停止/再開を行います。
4. タイムラインイベント、警告、DRCS、診断を確認します。
5. ASS と TTML を選択し、目的の保存オプションを選んでエクスポートします。
6. 通常の後続字幕ワークフローで結果を開き、テキスト、タイミング、レイアウト、ルビ、色、DRCS、操作性の不具合を記録します。
7. 候補版をアンインストールし、アプリケーションファイルが削除され、ユーザーが選択したエクスポートは残ることを確認します。

`docs/corpus.md` にある既存のオプトイン式コーパス検査とネイティブプレビュー検査は、引き続き補助的証拠となります。インストール済みアプリケーションのワークフローを置き換えるものではありません。

## 公開可能な結果

リリースノートでは、次の形式で概要を公開できます。

```text
Candidate: <tag> @ <commit>
Windows: <edition/build>; GPU class: <vendor/model>
Private fixtures: terrestrial N, BS N, long N, damaged N
Passed: N / N required matrix rows
Skipped: <rows and reason>
Known failures: <issue links or concise descriptions>
No recording bytes, captions, programme metadata, or screenshots published.
```

未署名 Windows Alpha を進められるのは、すべての必須行が合格した場合、または `release-checklist.md` で許可されたプライベートコーパスゲートのスキップをリリースノートで明示した場合に限ります。必須行の不合格はリリースを阻止する条件であり、マトリクスを緩和する理由にはなりません。
