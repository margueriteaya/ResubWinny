この画像は、意図するテレビ視聴時の結果を定めます。すなわち、1920×1080 の論理字幕プレーン、ARIB 対応フォントの選択、個別に配置されたテキスト領域、ソースの前景色・背景色・ストローク色、および親文字との視覚的な結び付きを保つルビです。これは B62 トランスポートのフィクスチャではなく、この画像にない B62 機能を推測する根拠にもなりません。

## 実装契約

B24 ルートが正式な基準です。プロジェクト所有の C ABI は、libaribcaption に `Rounded M+ 1m for ARIB` を使用して RGBA を直接生成するよう要求します。ルビと背景を有効にし、DRCS 置換を無効にし、領域を統合し、レンダラーのストローク幅には `2.0` を使用します。ResubWinny は、アーカイブとネイティブプレビューコンポジターを通じてその画像を保持します。Svelte UI もブラウザーのテキストエンジンも再描画しません。

B62/ARIB-TTML ネイティブレンダラーは、異なるビジュアル言語ではなく、同じ視聴者向けの関係性を目標としなければなりません。2K/4K/8K の source coordinates は、その表示プレーンから実際の video-content viewport へ比例 mapping されなければなりません。現在の 1920×1080 論理プレーンは中間 texture に過ぎません。横書きルビ、縦書きルビ、縦書き約物、および放送で直接的なアウトライン宣言が繰り返されなかった場合に使用する Rounded M+ の受信機基準の黒いストロークについて、ビジュアルゴールデンがあります。明示的な `tts:textOutline="none"` は引き続き正式な指定です。この B24 スクリーンショットとのピクセル単位の比較は、意図的に受け入れテストとしていません。このスクリーンショットには、対応する B62 ソース TTML、タイミング、領域メタデータ、スタイルペイロードが存在しないためです。新しい B62 セマンティクスは、適法なソースサンプルとリファレンスキャプチャが揃うまで、検証済みとしてはなりません。

## レビュールール

B24 ブリッジ設定、字幕プレーンの合成、フォントリソース、または B62 のテキスト・ルビ・ストロークのレイアウトを変更する場合は、影響を受ける PNG ゴールデンとともにこの画像をレビューしてください。WebView CSS で補正したり、汎用フォントに置き換えたり、合成例だけを根拠に視覚的同等性を主張したりしてはなりません。
