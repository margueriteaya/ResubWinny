# ARIB STD-B62 / ARIB-TTML 互換性

ResubWinny は ARIB-TTML をブラウザー CSS ではなく、字幕データ形式として扱います。トランスポートおよび XML デコーダーはレンダラーから独立したままであり、不明なアセットは字幕として推測されず、生の証拠として保持されます。

視聴者向けの視覚的ベースラインは [`libaribcaption` screenshot0](visual-reference.md) です。B24 は引き続き libaribcaption でレンダリングされた RGBA を使用し、B62 の作業はブラウザーレイアウトを使わずに、同じ論理プレーンとフォント・ルビ・背景・ストロークの関係へ収束しなければなりません。

本プロジェクトでは `makeding/aribb62.js` の公開挙動を参照としてレビューしています。レビュー対象の `74304d40a5b8556be1148e123ae70d60f937ecf5` はパッケージメタデータで MIT を宣言しています。しかし、リポジトリと GitHub のライセンス情報には独立した `LICENSE` ファイルがありません。再配布可能な著作権表示とライセンステキストが得られるまで、ResubWinny は独自に検証したセマンティクスを Rust バックエンドへ移植し、当該ソースはベンダー化しません。とりわけ、ブラウザー向けのストロークレンダリングを規範的な ARIB 実装と見なしたり、暗黙にアーカイブモデルへ取り込んだりしてはなりません。

## 現在のセマンティックマッピング

| ARIB-TTML の対象事項 | ResubWinny の挙動 |
| --- | --- |
| `lrtb`, `rltb` | TTML `horizontal-tb` に正規化され、ソースの `tts:direction` が明示的に上書きしない限り、導出された `ltr`/`rtl` 方向を保持します。ネイティブプレビューは一般的な Unicode 双方向シェーピングではなく、有界の文字セル RTL 配置を使用します |
| `tblr` | `vertical-lr` に正規化されます |
| `tbrl` | `vertical-rl` に正規化されます |
| `arib-tt:ruby` / `ruby` / `rt` | 安全なインライン TTML 本文とアーカイブレコードに保持されます。基本水平ネイティブプレビューは `arib-tt:ruby` 注釈 span をその `xml:id` ベース span に解決し、注釈をインライン本文レンダリングから除去します |
| 継承された `div` のタイミングとスタイル | 字幕区間が出力される前に解決されます |
| 標準の名前付き TTML 色 | 既存の `#RRGGBB[AA]` サポートに加え、`black`、`white`、`red`、`green`、`blue`、`yellow`、`cyan`、`magenta`、`transparent` を大文字小文字を区別せずネイティブに解析します。ブラウザーの CSS 色パーサーは使用しません |
| 水平 `br`/改行、`textAlign`、`displayAlign`、`lineHeight` | ネイティブプレビューは明示的な改行を保持し、`start`/`end`/`left`/`right`/`center` で各有界行をレイアウトし、`before`/`center`/`after` で行ブロックを配置します。`start` と `end` は解決済みの LTR/RTL 方向に従います。これはネイティブ RGBA レイアウトであり、ブラウザーへのフォールバックではありません |
| 宣言または証拠のある表示プレーン | 有効なルート `tts:extent` が正式な値であり、source coordinate space を定義します。それがなければ論理 2K が既定値のままです。パーサーが正規の 3840×2160 または 7680×4320 を推論するのは、完全なピクセル `origin`/`extent` ジオメトリが少なくとも一方の軸で論理 2K を超え、かつそのプレーン内に収まる場合だけです。領域の origin/extent は独立した水平/垂直比率を使用し、ピクセルフォントサイズ、行高、字間、直接指定されたアウトライン幅には有界の均一比率を使用します。現在の `1920×1080` RGBA plane は backend の中間 texture に過ぎません。acceptance は、黒帯を除いた video-content viewport への比例 mapping により、window size、DPI、fullscreen の変化を通じて視聴者相対領域が維持されることを基準とします。曖昧な入力は決して推測しません |
| `subt://` 画像/フォントと `smpte:image` | 数値の `subt://<index>` 参照は、同じ `packet_id + mpu_sequence_number` リソース状態に対してのみ解決されます。有界の `subsampleNumber` リソースが存在する場合、アーカイブはそのスコープとサブサンプル番号をキーとする可逆な `resource_evidence` レコードを書き込み、データ型、バイト長、有界の形式検証、base64 ペイロードを保持します。アーカイブプレビューリーダーは、一致する小さな構造的に完全な PNG だけを低頻度リソースプレビューとして公開します。フォントと PNG 以外のリソースはレンダリング済みテキストではなく証拠のままです。欠落または不完全なマップは明示的に `unresolved` のままです。検出された MPT アセットは有界の `asset_evidence` レコードとして出力され、完全な非 `stpp` MPU/MFU ペイロードは `dump-tlv` により、一致するスコープキーを持つ `mmt_asset_payload` 生証拠として抽出できます |
| 明示的な `origin`/`extent` を持つ水平テキスト | バックエンドは、同梱の ARIB 用 Rounded M+ 1m とソースの前景/背景 RGBA を使用して、有界の 1920×1080 RGBA プレーンへラスタライズできます。同梱フォントにないグリフは計数され、豆腐または汎用グリフに置き換えず空白のままにします。これは初期のネイティブプレビューパスであり、完全な B62 レンダラーではありません |
| `vertical-lr` / `vertical-rl` | バックエンドには有界のネイティブ縦書きモードがあります。文字セルを縦に進め、領域を超えると新しい列を開き、左右の列方向に従います。同梱 ARIB フォントに明示的な Unicode 縦書き表示形が存在する場合、句読点をその形へマッピングします。CJK/全角グリフは正立したままです。ASCII とラテングリフはネイティブの時計回りビットマップ回転を使用し、分類されない文字体系は推測せず正立したままです。明示的に関連付けられたルビ注釈はベースセルの横にラスタライズされ、自動折り返し列をまたぐ有界の継続（`ttml-vertical-ruby-basic-native`）も含みます。注釈は既定でベースフォントサイズの半分ですが、明示的な `tts:color`、`tts:fontSize`、`tts:letterSpacing`、直接 opacity、サポートされる直接 `tts:textOutline` は保持されます。1 桁または 2 桁の ASCII 数字を含み、直接 `tts:textCombine="all"` または `digits` が指定された span は、1 つの縦書きセル内で水平にラスタライズされます。より長い並びは縦書きのままです。完全な B62 方向テーブルとソース固有のルビ配置は、適法なコーパス比較を待つ必要があります。 |
| 安全な `rich_body` span スタイル | 有界の token 抽出はタグ間の通常の本文を保持し、各ソース span の明示的な前景色、フォントサイズ、字間、直接 opacity をネイティブテキストプレビューへ適用します。明示的に関連付けられたルビテキスト（`tts:ruby="text"` または `arib-tt:ruby`）はインライン化されず構造を維持し、サポート対象の固有の注釈表示プロパティを伴います。 |
| 水平 `ruby` のベース/テキスト対 | ネイティブプレビューは `tts:ruby="text"` span を直前の連続する `tts:ruby="base"` グループに、または `arib-tt:ruby` 注釈 span をその `xml:id` ベース span に関連付けます。1 つの注釈は解決済みベースグループ全体の中央に配置されます。注釈フォントサイズは既定でベースフォントサイズの 0.5 ですが、明示的にサポートされる注釈の色、フォントサイズ、字間、opacity、直接アウトラインが優先されます。スナップショットは `ttml-horizontal-ruby-basic-native` とレンダリング済みルビ数を報告します。非連続/重複するソース固有の B62 ルビ配置は、コーパス比較で配置規則が証明されるまでメタデータのままです。 |
| 直接 TTML `tts:textOutline` | 保守的なネイティブプレビューマッピングは、直接の TTML 名前付き色または `#RRGGBB`/`#RRGGBBAA` と `px` 幅を受け入れ、`none` を受け入れ、半径を 1–4 ピクセルに制限し、継承 opacity を適用します。アウトライン宣言が繰り返されていない Rounded M+/`丸ゴシック` 字幕は、受信機ベースラインの 2 px 黒ストロークを使用し、ネイティブ PNG golden で保護されます。明示的な `none` はこれを無効にします。未サポート構文は、創作されたアウトラインになるのではなくメタデータのままです |
| `arib-tt:border` とブラウザーストローク CSS | 自動的に `tts:textOutline` へ変換しません。これにより、非標準のアウトライン等価性を主張することを避けます |
| 不明な書字モードまたは拡張 | ソーススタイルメタデータとして保持し、診断/生データ経路を通じて報告します |

ASS は依然として近似です。位置、色、フォントサイズ、および一部のテキストスタイルは保持できますが、B62 の書字、ルビ、アニメーション、ビットマップリソース、放送ストロークセマンティクスの可逆な表現ではありません。

## 計画中の増分

1. 実装済みの有界ルビグループ化と保守的な縦書き方向パスを適法な B62 キャプチャと比較し、コーパスで実証された規則だけを拡張します。
2. 実装済みの受信機ベースラインストローク golden を追加のフォントファミリーまたは構文へ拡張する前に、ユーザー検証済み ARIB キャプチャと比較します。ブラウザーの `text-shadow` または `-webkit-text-stroke` からそれらの拡張を推論してはなりません。
3. 現在の B24 RGBA コンポジターおよび基本水平ルビ TTML プレーンのネイティブ視覚 golden を保持します。ネストしたタイミング、縦書きルビ、リソース URL、未サポート拡張を持つ B62 fixture は、適法な参照キャプチャと比較できる場合にのみ追加します。
