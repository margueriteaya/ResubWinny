# Windows 私有 Alpha 版驗收

此矩陣使用合法持有的日本廣播錄影驗證已封裝的應用程式。錄影、解碼後的字幕、節目名稱、本機路徑及螢幕擷取畫面皆須保密。發行時只能公布結果摘要、測試資料類別、位元組大小、時長、所產生發行成品的雜湊值，以及通過/失敗數量。

公開的通訊協定測試資料不能取代此矩陣，也不應只為了模仿特定廣播業者的錄影而加入合成廣播串流。剖析器單元測試資料仍適合用於有界的畸形輸入迴歸測試。

## 候選版本識別資料

測試前記錄下列欄位。這些資料必須與候選版本目錄中的 `RELEASE-MANIFEST.json` 及 `SHA256SUMS.txt` 相符。

| 欄位 | 結果 |
| --- | --- |
| 發行標籤 / 提交 | 待定 |
| 安裝程式名稱 / SHA-256 | 待定 |
| `RELEASE-MANIFEST.json` SHA-256 | 待定 |
| libmpv `SOURCE-RECEIPT.json` SHA-256 | 待定 |
| Windows 版本 / 組建 | 待定 |
| CPU / GPU / 顯示卡驅動程式 | 待定 |
| 全新安裝或升級路徑 | 待定 |

在備註中使用 `terrestrial-a` 之類不透明的本機測試資料 ID。不得記錄節目標題、廣播業者節目表、來源檔名或檔案系統路徑。

## 相容性矩陣

| 類別 | 所需的封裝版工作流程證據 | 通過標準 | 結果 |
| --- | --- | --- | --- |
| 地面波 TS | 偵測服務及 B24 軌道；預覽；時間軸；匯出 ASS 及 TTML | 所選軌道正確、記憶體有界、預覽可用、經驗證的匯出檔案非空白 | 待定 |
| BS TS | 偵測服務及字幕軌道；預覽；時間軸；匯出 | 不假設固定 PID 或檔名，仍可取得相同的端對端結果 | 待定 |
| 長節目（2–4 小時） | 開啟、建立索引、跳轉至接近開頭/中間/結尾處、預覽、匯出 | 不出現無界記憶體成長、時間軸過時、跳轉鎖死或最終成品不完整 | 待定 |
| DRCS | 檢查報告、對應已知字符、讓未知字符維持未解析、匯出 | 對應可持久保存；後援狀態仍然可見且可診斷 | 待定 |
| 多個服務/軌道 | 切換所選字幕軌道並分別匯出 | 預覽、事件數量、證據及匯出僅跟隨所選邏輯軌道 | 待定 |
| 損毀/截斷的錄影 | 檢查並轉換合法持有的損毀或截斷擷取檔 | 處理有界、診斷明確、不捏造服務/軌道、可復原的輸出仍有效 | 待定 |
| BS4K M2TS/私有 PES | 僅執行已有真實樣本證據支持的路徑 | 結果嚴格表述為支援 M2TS/私有 PES TTML | 待定 |
| TLV/MMTP | 僅在有合法真實樣本時執行 | 結果維持實驗性且證據優先；不得據此宣稱普遍支援 BS4K/8K | 不設門檻 |

## 端對端字幕工作流程

執行已安裝的應用程式，而不是開發伺服器或 Cargo 測試工具：

1. 對照 `SHA256SUMS.txt` 驗證安裝程式雜湊值，然後在確認文件所述的未知發行者警告後安裝。
2. 開啟錄影，確認偵測到的容器、服務、節目中繼資料證據及可用字幕軌道。
3. 啟動原生預覽；在多個位置跳轉及暫停/繼續。
4. 檢查時間軸事件、警告、DRCS 及診斷資訊。
5. 選取 ASS 及 TTML，選擇預期的保存選項，然後匯出。
6. 在一般後續字幕工作流程中開啟結果，並記錄任何文字、時間、版面配置、注音、色彩、DRCS 或可用性缺陷。
7. 解除安裝候選版本，確認應用程式檔案已移除，而使用者選擇的匯出檔仍然保留。

`docs/corpus.md` 中現有的自願加入語料庫檢查及原生預覽檢查仍屬輔助證據，不能取代已安裝應用程式的工作流程。

## 可公布的結果

版本資訊可依下列格式公布摘要：

```text
Candidate: <tag> @ <commit>
Windows: <edition/build>; GPU class: <vendor/model>
Private fixtures: terrestrial N, BS N, long N, damaged N
Passed: N / N required matrix rows
Skipped: <rows and reason>
Known failures: <issue links or concise descriptions>
No recording bytes, captions, programme metadata, or screenshots published.
```

只有在每個必要項目皆通過，或版本資訊明確指出 `release-checklist.md` 允許略過某個私有語料庫門檻時，才可繼續發布未簽署的 Windows Alpha 版。任何必要項目失敗都會阻止發布，不能以此為由降低矩陣要求。
