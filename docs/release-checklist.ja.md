# リリースチェックリスト

[简体中文](release-checklist.md) · [繁體中文](release-checklist.zh-TW.md) · [日本語](release-checklist.ja.md) · [English](release-checklist.en.md)

> **規範に関する注記：** 簡体字中国語版が唯一の正式な情報源です。他言語版は同期された翻訳であり、文言に曖昧さや矛盾がある場合は、簡体字中国語版が優先されます。

ResubWinny には 3 つの公開リリース階層があります。ある階層に合格しても、次の階層の準備ができていることにはなりません。

1. **ソースリリース**では、タグ付きのソースアーカイブのみを公開します。
2. **未署名 Windows Alpha**では、初期の公開テスト向けに、未署名であることを明示した Windows ビルドを公開し、完全なハッシュ、来歴、対応するソース、ライセンス資料を提供します。
3. **署名済み安定版**では、保護されたコード署名と、安定版 Windows リリースに求められる、より厳格なインストールおよびアップグレード保証を追加します。

再配布可能な放送録画が存在しないことは、リリースの不備ではありません。実際の録画は、法的理由により非公開の検証環境でのみ保持およびテストされます。公開 CI は構築されたプロトコルフィクスチャを使用し、録画のバイト列、その録画から派生した字幕、スクリーンショットを公開せずにテスト結果を公開します。リリースノートでスキップしたゲートを明記します。公開の合成チェックに合格していれば、非公開コーパスゲートをスキップしてリリースを進められます。

## ソースリリース

- [ ] タグ付きリビジョンが `scripts/check.ps1` に合格している。
- [ ] `scripts/verify-repository.ps1` が、生成済み、ダウンロード済み、非公開コーパス、ネストしたリポジトリ、または追跡対象としては大きすぎるファイルを報告しない。
- [ ] すべてのパッケージバージョンと UI のバージョンラベルが同じリリースを表している。
- [ ] `THIRD_PARTY_NOTICES.md`、`third_party/versions.json`、`docs/dependency-licenses.md` が最新である。
- [ ] ビルドで `libaribtlv` feature を有効にする場合、同梱する libaribtlv 0.6.1 と Zlib 1.3.2 の固定コミット、snapshot hash、license を記録し、`cargo test -p arib-caption-worker --features libaribtlv` に通過する。system Zlib または開発者の外部 checkout に依存してはならない。
- [ ] アーキテクチャおよびバックエンド契約に関する記述で、検証済みルートと実験的な TLV/MMTP の挙動を区別している。
- [ ] `scripts/package-source.ps1` が、クリーンなタグからソースアーカイブとチェックサムを生成する。
- [ ] リリースノートに、既知の制限事項とスキップしたコーパスゲートを明記している。

## 未署名 Windows Alpha

ソースリリースの全項目を完了したうえで、さらに以下を必須とします。

- [ ] Worker、フロントエンド、デスクトップの各バイナリが、固定されたワークフローでビルドされている。
- [ ] バンドルされるものと完全に同一の libmpv バイナリと、対応するソースの完全なアーカイブが、同じレビュー済みワークフローで生成され、一緒に公開されている。
- [ ] `SOURCE-RECEIPT.json`、DLL のハッシュ、インストーラーのハッシュ、通知が一致している。
- [ ] インストーラーに MPL-2.0、libaribcaption、libaribtlv、Zlib、libmpv、Rounded M+ の通知が含まれ、libmpv を交換可能な状態にしている。
- [ ] リリースタイトルとノートに **未署名 Windows Alpha** と記載し、Windows が発行元不明の警告を表示する可能性を説明し、コード署名によって真正性が保証されているかのように示唆していない。
- [ ] ダウンロード可能なすべてのアーカイブ、実行ファイル、インストーラーの SHA-256 チェックサムと、それらのビルドに使用した正確な Git タグおよびコミットがリリースに含まれている。
- [ ] パッケージ済み実行ファイルで、ネイティブプレビューのスモークテスト、シーク／一時停止／再開、オーバーレイのタイミング、サイズ変更／DPI、長時間 4K パフォーマンスの各ゲートに合格している。
- [ ] インストール、アンインストール、クリーンマシンでの起動をテストしている。リリースノートに Alpha の制限事項とスキップした非公開コーパスゲートを明記する。パッケージ化ワークフローの結果は `windows-alpha-acceptance.md` を使用して記録する。

コード署名は、この階層の前提条件ではありません。一方で、バンドルされた libmpv ビルドに対応するソースとライセンスへの準拠は引き続き必須です。ビルドを Alpha または未署名と表示しても、この要件は免除されません。

## 署名済み安定版

未署名 Windows Alpha の全項目を完了したうえで、さらに以下を必須とします。

- [ ] リリース用の実行ファイルとインストーラーが、保護されたプロジェクト署名 ID で署名されている。
- [ ] 最終的な公開成果物をダウンロードした後、署名と証明書 ID を検証している。
- [ ] サポート対象のすべてのインストーラーパスについて、インストール、アップグレード、アンインストール、ロールバック、クリーンマシンでの起動をテストしている。
- [ ] 安定版のリリースノートに、サポート対象の Windows バージョンとアップグレード互換性ポリシーを記載している。

選択した階層のすべての項目が完了するまで、自動化によってその階層を公開してはなりません。ワークフローは非公開テストの成果物を引き続きアップロードできます。特に、署名が設定されているかどうかにかかわらず、バンドルされるものと完全に同一の libmpv の対応ソース、レシート、ハッシュ、通知が揃っていない Windows バイナリは公開してはなりません。
