# libmpv のソースとリリース準拠

[简体中文](libmpv-source-compliance.md) · [繁體中文](libmpv-source-compliance.zh-TW.md) · [日本語](libmpv-source-compliance.ja.md) · [English](libmpv-source-compliance.en.md)

> **規範に関する注記：** 簡体字中国語版が唯一の権威ある原文です。他言語版は同期した翻訳であり、文言に曖昧さまたは矛盾がある場合は簡体字中国語版を優先します。

ResubWinny は Windows で置換可能な LGPL ビルドの libmpv を動的にロードします。同梱開発 DLL は固定されハッシュ検査されますが、その上流ビルドは変動する依存関係ブランチを使用し、完全なソースキャッシュをリリース成果物として公開していません。そのため現在の DLL は、開発と私的テストだけに承認されており、ResubWinny 初の公開バイナリーリリースには使用できません。

## ビルドプロファイル

基本 Tauri 設定は libmpv バイナリーを同梱しません。したがってライブラリーをダウンロードまたは再配布せずにアプリケーションとインストーラーをビルドできます。この場合プレビューには、利用者が提供する互換ランタイムが必要です。通常のワンコマンドビルドでは、開発/私的テスト向けの実用パッケージのため、明示的な Windows libmpv 設定を使います。

```powershell
./scripts/build.ps1
```

外部ランタイムパッケージも同様に明示的です。

```powershell
./scripts/build.ps1 -Libmpv External
```

どちらのプロファイルも公開リリース規則を弱めません。`libmpv-2.dll` を含むパッケージは、対応する完全な対応ソース、ソース受領書、通知、バイナリーハッシュをともに公開するまで公開してはなりません。同じ検証済み対応ソース成果物を後の ResubWinny ビルドで再利用できるのは、同梱 DLL ハッシュが完全に同一である間だけです。

## 必須の公開リリースビルド

リリースビルドは `third_party/versions.json` に記録されたコミットから実行し、パッケージをダウンロードまたはコンパイルする前にレビュー済みの LGPL 専用パッチを適用しなければなりません。同じビルドジョブは、次を保持しなければなりません。

1. 正確なビルドレシピのチェックアウト。
2. パッチ適用済みの `mpv-winbuild-cmake` チェックアウト。
3. ダウンロードと更新後の完全な `src_packages` ディレクトリ。
4. 得られた DLL とインポートライブラリーのハッシュ。
5. パッケージのコミット/状態受領書。
6. 再ビルドに必要なすべてのビルドオプション、パッチ、ライセンス文、スクリプト。
7. 記録済みの runner、ツールチェーン、ネイティブパッケージ環境。

これら三つのソースディレクトリと、新規ビルドした DLL/インポートライブラリーを含む展開ディレクトリに対して `scripts/package-libmpv-source.ps1` を実行し、同じジョブが出力したビルド環境記録を渡します。このスクリプトはコアパッケージが欠けたソースキャッシュを拒否し、固定レシピとツールチェーンの祖先、LGPL 設定を検証し、すべてのソースパッケージを記録し、ハッシュアドレス指定の対応ソースアーカイブを作成します。

このアーカイブと `SOURCE-RECEIPT.json` は、その libmpv DLL を含むすべての公開バイナリーの横にアップロードしなければなりません。変更可能なリポジトリブランチ、GitHub Actions 実行 URL、または mpv 本体だけを含むソースアーカイブでは不十分です。

## libmpv の更新

将来の libmpv 更新は、以下を含む一つの不可分な変更としてのみ受け入れます。

- 新しいバイナリー、インポートライブラリー、ヘッダー、ハッシュ。
- 同じビルドで生成した正確なソースアーカイブと受領書。
- 更新済みの通知と `third_party/versions.json`。
- エクスポートシンボルと置換可能性の検査。
- プレビュー、seek、オーバーレイクロック、DPI、2K/4K/8K 性能回帰。
- 明示的なロールバック成果物。

ランタイムコンポーネントが libmpv をダウンロードまたは黙って置換することはできません。
