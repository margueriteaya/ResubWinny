# プレビュー構成決定
外部 `mpv.exe` サイドカーは製品要件ではありません。ResubWinny は、独自の動的 `libmpv` クライアント ABI に移行しています。Windows x86_64 ランタイムは、置換可能な LGPL 依存関係としてバンドルされています。macOS と Linux は、プラットフォームランタイムと同じ ABI コントラクトを使用します。

| バックエンド | プラットフォーム | キャプションの忠実性 | 主なトレードオフ |
| --- | --- | --- | --- |
| `libmpv-render` | Windows/macOS/Linux | 最高;ビデオとライブラリキャプション RGBA を 1 つのサーフェスで構成 | libmpv 統合とネイティブテクスチャ/サーフェスループが必要です |
| MPV `overlay-add` | MPV プラットフォーム | 低周波数 RGBA フレームの場合は「高」 | Raw ピクセルのアップロードと mpv バージョン/VO の制約 |
| ネイティブウィンドウオーバーレイ | まずはWindows | 高い | HWND/Z オーダー、サイズ変更、DPI、およびプラットフォーム固有のコード |
| WebView イメージレイヤー | 全て | アーカイブの検査に適しています | 埋め込まれたネイティブ子ウィンドウを確実にカバーできない |
| ASS 字幕トラック | 全て | 近似 | 正確な ARIB 文字セル、ルビ、DRCS、およびバックグラウンドセマンティクスが失われます |

選択された Windows ルートは `libmpv-render` です。ビデオとキャプションを同じプロジェクト所有の WGL サーフェスに保持し、WebView/ネイティブウィンドウのスタッキングの問題を回避します。`wid` と `overlay-add` クライアントは、レンダリング API または WGL の起動が失敗した場合のソースごとの互換性フォールバックとしてのみ残ります。ResubWinny は `mpv.exe` を開始せず、JSON 名前付きパイプも使用しません。macOS と Linux は同じキャプションモデルを使用しますが、ネイティブレンダーサーフェスはまだ実装されていません。

型指定された `get_preview_capabilities` API は、UI を Windows 固有の詳細に依存させることなく、この選択肢を公開します。レンダリングルートとそのクライアントオーバーレイフォールバックの両方で、Tauri バックエンドは、型指定された `sync_preview_overlay` オペレーションを通じて mpv 時間をサンプリングし、返されたネイティブキャプションプレーンをアップロードする前に前のプレーンと比較します。WebView はその操作をスケジュールできますが、メディア時間の計算、キャプションの作成、フォールバッククロックの実装は行いません。したがって、キャプションプレーンが変更されても、別の raw ピクセル IPC 転送は発生しません。これにより、キャプションタイムラインをプリロードすることなく、長くまばらな録音が制限された状態に保たれます。変更された RGBA プレーンはプレビューごとの一時 BGRA ファイルに書き込まれ、文書化された `overlay-add` ファイル/オフセット引数とともに mpv に渡されます。一時ファイルはプレビューが停止すると削除されます。Tauri アーカイブリーダーは、前方専用カーソルと最大 128 のアクティブな間隔を保持します。逆方向にシークすると、その境界付きカーソルがリセットされるため、複数時間にわたるタイムラインがメモリにロードされることはありません。mpv 時間クエリのタイムアウトは短いです。IPC の準備ができていない場合、バックエンドは `awaiting-player-time` を返し、ローカルクロックタイムラインを作成するのではなく、最後のプレーンを所定の位置に残します。

`get_preview_runtime` は、ロードされたランタイムパスと、そのランタイムが libmpv render API をエクスポートするかどうかを報告します。Windows では、完全なレンダリング API はデフォルトでネイティブレンダリングルートを選択します。特定のソースがそのルートを初期化できない場合、そのプレビューはクライアントオーバーレイルートに安全にフォールバックします。専用のネイティブスレッドは、プロジェクトが所有する WGL コンテキスト、`vo=libmpv` インスタンス、およびレンダリングコンテキストを所有します。`loadfile` の前にレンダーコンテキストを作成し、制限された制御/サイズ変更/時間メッセージを処理し、保留中のフレームを最大 16 ミリ秒に 1 回ポンプし、デフォルトのフレームバッファ上に表示し、同じ WGL コンテキストが最新のままである間にコンテキストを解放します。これにより、バックエンド内で脆弱な ABI/ライフタイムとスレッドの順序が維持されます。

同じレンダリングスレッドは、バックエンドで構成された BGRA キャプションプレーンのみを受け入れます。プレーンが変更されると、境界付きの OpenGL テクスチャがアップロードされ、mpv ビデオフレームの後にそのテクスチャがブレンドされます。WebView はビデオフレームを受信したり、キャプションレイアウトを実行したりすることはありません。libmpv に表示に適したビデオアスペクトを要求し、キャプションプレーンを結果のレターボックス/ピラーボックスビューポートにマップします。メディアパラメータの準備ができていない場合は、安全に全面にフォールバックして再試行します。ランタイムが完全なレンダリング API を公開すると、Windows ルートは型付き機能コントラクトを通じて利用可能になります。`hwdec=auto-safe` を要求し、利用可能な場合は libmpv の実際の `hwdec-current` 選択を報告します。これは、互換性のあるコピーバックアクセラレーションを使用する可能性がありますが、ゼロコピー D3D/ANGLE ハードウェアデコード要求ではありません。以下に説明するリアルコーパス Windows 4K ロングゲートが完成しました。独立した 2K/8K ゲート、参照スクリーンショットの比較、DPI レビューは、隠れたフォールバックではなく、リリース品質の作業のままです。

`scripts/validate-preview.ps1` は Windows ネイティブのスモークゲートです。`ARIB_FIXTURE_DIR` を通じて提供される合法的なローカル記録を使用し、実際の WGL ホストを作成し、バンドルされた libmpv ランタイムをロードし、専用のレンダーワーカーを開始します。また、不均一デコードされたビデオフレームバッファと 1 つのバックエンド RGBA キャプションテクスチャのアップロードとワーカーエラーなしのクリアが必要です。同じレンダースレッドで WGL バックバッファをキャプチャし、アップロードされた不透明な緑色のテストテクスチャがキャプチャされた RGBA ピクセルに存在することをアサートします。`bs4k_test_2.ts` 煙は 2026-07-29 に通過しました。これにより、ライフサイクル、TS オープニング、デコードされたビデオ、ネイティブの存在、テクスチャブレンド、および境界付きフレームバッファのリードバックが検証されます。煙は 3840 × 2160 HEVC ソースを実行し、ブレンドされたプレーンを 1920 × 1080 でキャプチャし、ネイティブサーフェスのサイズを 3840 × 2160 に変更します。また、保持された寸法と測定可能なプレゼンテーションリズムが必要です。これは Windows ルート回帰ゲートであり、8K スループットやゼロコピーデコードを主張するものではありません。参照スクリーンショットのキャプチャ、アプリケーションの DPI レビュー、および画像の差分の承認は、引き続き別個のゲートとなります。

`-Long` を渡すと、しきい値付きの 120 秒の 4K 再生ゲートが追加されます。同じインプロセスネイティブルートを実行し、3840x2160 のサーフェスをアクティブに保ち、3 つの完全な 1920x1080 キャプションプレーンの置換を実行し、一時停止、再開、正確なシーク、および制限付きシャットダウンを実行します。デフォルトのゲートしきい値は、少なくとも 20 提示フレーム/秒、最大 10 秒の起動、1 秒の制御/キャプション更新レイテンシー、3 秒のシャットダウン、2048 MiB の絶対ワーキングセット、およびウォームアップ 4K ベースライン後の 512 MiB の増加です。結果は、`build/validation/` の下にスキーマバージョン管理された JSON として書き込まれます。

2026 年 7 月 30 日の実際の 3840x2160 HEVC `bs4k_test_2.ts` に対する実行は、`d3d11va-copy` で 120 秒間 34.74 提示フレーム/秒を維持し、1.69 秒で開始し、1526.9 MiB でピークに達し、ウォームアップ後に 111.9 MiB 増加し、最大で完全なキャプションプレーンをアップロードしました。34.6 ミリ秒、最大 14.7 ミリ秒でコントロールを完了し、レンダリングエラーなしで 337 ミリ秒で停止しました。これらは、この Windows マシンの回帰測定値であり、明示的な合否しきい値を超える普遍的なハードウェア要件ではありません。ハーネスは Cargo のテストプロファイルを使用しますが、バンドルされた libmpv バイナリ、WGL サーフェス、デコーダ、および合成ルートはアプリケーションで使用されるものと同じネイティブランタイムです。パッケージ化されたリリースの再実行は、別個のアーティファクト受け入れステップとして残ります。
